跑通 Vue -> Go -> Python 全链路

作为一个 AI 应用开发的新手，第一周的目标很明确：打通 Vue、Go、Python 三者的链路，跑通一个最小 Demo。

这一周对我来说，心理波动特别大。我遇到了新手常犯的所有错：

  • 环境配置装半天，还是报错。
  • 一个小问题（比如跨域、包导入），我死磕了1.5 个小时。
  • 方案被打乱，想放弃的念头闪过好几次。

但是，我没有退。

我把遇到的坑都记了下来，死磕到底。今天晚上，当我看到页面上请求发出、Go 接口处理、Python 返回结果，最终在 Vue 上展示出来的那一刻，所有的焦虑都变成了巨大的成就感。
这不仅仅是一个 Demo，这是我未来所有 AI 产品的地基。

二、 技术架构：我是怎么搭的？

这次我搭建了最经典的前后端分离 + AI 调用架构：

  1. 前端 (Vue3 + Vite)：负责展示页面，发送请求，接收结果。
  2. 后端 (Go)：负责接收前端请求，做逻辑中转，调用 Python 脚本。
  3. AI 逻辑 (Python)：负责具体的 AI 能力调用（如调用豆包 / 文心接口），并返回结果给 Go。
    链路流程：
    Vue页面(点击发送) -> Go接口(接收请求) -> Python脚本(调用AI) -> 返回结果给Go -> 返回给Vue

四、 我遇到的 “大坑” 与解决方案（重点！）

这一周最宝贵的不是跑通代码，而是解决了以下几个卡点。

坑 1：Go 调用 Python 脚本时，路径找不到

  • 现象：代码写对了，但 Go 执行命令时报错，说找不到ai_api.py。
  • 原因：exec.Command 执行时的工作目录不是项目根目录。
  • 解决：
    1. 使用绝对路径。
    2. 或者在 Go 代码里先用os.Getwd()获取当前目录，再拼接路径。

坑 2：跨域问题 (CORS)

  • 现象：浏览器控制台报错 Access to XMLHttpRequest...。

  • 解决：在 Go 的 Gin 框架里加了一个 CORS 中间件（如上面代码所示），允许所有来源访问。

坑 3：环境变量冲突

  • 现象：Python 运行报错，提示找不到某个库。

  • 解决：确认是用pip3安装的库，并且确保exec.Command调用的是正确的python3解释器，避免使用虚拟环境导致的路径问题。

五、 写在最后

第一周结束，全链路跑通。

我知道，对于高手来说这只是一个简单的 Hello World。

但对于正在死磕的我来说，这是一座里程碑。

我也想告诉和我一样正在自学的朋友：

不要害怕卡壳，不要害怕拖延。

人类的大脑就是抗拒这种陌生的挑战。

但只要你像我一样，把大问题拆小、死磕到底、记录下来，

你会发现，每一次跑通，都是一次灵魂的升级。

下一周，我会在这个 Demo 上增加 AI 的真实能力，直到部署到线上。
